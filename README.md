# 五子棋项目架构说明

## 项目概述

本项目是一个基于 Windows API 的五子棋小游戏，使用 C 语言实现，界面、交互、棋盘状态和胜负判断分别由不同模块承担。

项目以窗口消息循环为核心，通过鼠标点击落子、定时器更新计时、Bitmap 资源完成界面绘制，形成一个轻量级的桌面应用。

## 文件结构

- [main.c](main.c) 负责程序入口、窗口注册、消息分发、界面绘制和鼠标交互。
- [game.c](game.c) 负责棋盘状态、落子校验、玩家切换和胜负判断。
- [game.h](game.h) 负责对外声明共享数据与函数接口，供多个源文件共同使用。
- `board.bmp`、`black.bmp`、`white.bmp`、`about.bmp` 分别用于棋盘、黑棋、白棋和说明窗口的图像显示。

## 总体架构

项目采用“界面层 + 规则层”的分层方式：

1. 界面层由 main.c 承担，负责创建主窗口和说明窗口，处理 WM_PAINT、WM_LBUTTONDOWN、WM_TIMER 等消息，并把用户操作转换为游戏动作。
2. 规则层由 game.c 承担，负责维护棋盘数组、判断位置是否合法、更新当前玩家、检测五连胜。
3. 接口层由 game.h 承担，统一暴露棋盘大小、全局状态和函数声明，保证主窗口逻辑与游戏规则逻辑解耦。

这种结构的优点是职责清晰：窗口相关逻辑集中在 main.c，规则变化主要影响 game.c，头文件只提供必要共享接口。

## main.c 职责

main.c 是程序的控制中心，主要完成以下工作：

- 注册主窗口类 GomokuWindow 和说明窗口类 PictureWindow。
- 创建 1024x790 的主窗口，作为游戏运行载体。
- 在 WM_CREATE 中加载棋盘、黑棋、白棋图像资源。
- 在 WM_PAINT 中绘制背景棋盘、根据 board 数组绘制棋子、显示计时文本。
- 在 WM_LBUTTONDOWN 中处理鼠标点击，完成坐标映射、尝试落子、重置游戏、打开说明窗口。
- 在 WM_TIMER 中维护游戏计时，每秒刷新一次界面。
- 在 WM_DESTROY 中释放图像资源并退出消息循环。

从控制流上看，main.c 不直接实现复杂规则，而是通过 TryPlace、ToGridX、ToGridY 等接口调用 game.c 中的逻辑函数，属于典型的事件驱动 UI 层。

## game.c 职责

game.c 是游戏规则的核心实现，包含以下内容：

- 全局棋盘数组 board，用 0、1、2 表示空位、黑棋、白棋。
- 全局状态 gamestatus，用于表示未开始、进行中、黑棋胜、白棋胜。
- currentPlayer 用于记录当前轮到哪一方落子。
- initBoard 用于清空棋盘。
- PlacePiece 用于校验落子位置是否合法。
- TryPlace 用于实际执行一次落子，并在落子后判断是否获胜。
- GetNextPlayer 用于切换玩家。
- ToGridX 和 ToGridY 用于把鼠标坐标转换为棋盘索引。
- CheckWin 用于检查横、竖、两条斜线方向是否满足五连。

其中 TryPlace 是规则层的关键入口：它先校验位置，再写入棋盘状态，然后调用 CheckWin 判断胜负，最后切换玩家。

## game.h 设计

game.h 定义了整个项目共享的接口与常量：

- BOARD_SIZE 固定为 15，表示 15x15 棋盘。
- board、currentPlayer、gamestatus、LOCX、LOCY 以 extern 形式对外共享。
- initBoard、PlacePiece、GetNextPlayer、TryPlace、ToGridX、ToGridY、CheckWin 作为核心函数对外声明。

这种头文件设计使 main.c 可以直接读取棋盘状态并调用规则函数，而不需要关心 game.c 的具体实现细节。

## 数据流

一次完整的用户交互通常经过以下流程：

1. 用户在主窗口内单击鼠标。
2. main.c 的 WM_LBUTTONDOWN 接收坐标并调用 ToGridX、ToGridY 进行棋盘映射。
3. main.c 通过 TryPlace 请求规则层尝试落子。
4. game.c 修改 board，并根据 CheckWin 判断是否结束。
5. main.c 触发界面重绘，WM_PAINT 根据 board 重新绘制棋盘和棋子。
6. 若一方获胜，程序通过消息框提示结果，并把 gamestatus 更新为胜负状态。

整个过程遵循“输入事件驱动状态变化，状态变化驱动界面重绘”的模式。

## 资源与界面

项目界面不使用复杂控件，而是以位图资源完成渲染：

- `board.bmp` 作为棋盘背景。
- `black.bmp` 和 `white.bmp` 作为黑白棋子图像。
- `about.bmp` 用于说明窗口。

主窗口通过 BitBlt 将位图直接绘制到客户区，从而保持实现简单，并减少对标准控件的依赖。

## 当前实现特点

- 使用 Windows 原生消息机制，适合学习 Win32 程序的窗口创建、绘制和事件处理。
- 游戏状态全局化，代码简洁，但后续如果扩展为更大的项目，可以考虑把状态封装到结构体中。
- 棋盘尺寸和坐标映射采用固定数组，便于快速定位落点。
- 胜负检测采用四方向扫描，逻辑直观，适合五子棋规则。

## 运行说明

该项目依赖 Windows 平台和 GDI 图形接口，运行时需要保证可执行文件与位图资源位于同一目录下，以便程序从 exe 所在目录加载图片。

如果使用 Visual Studio 或其他支持 Win32 C 项目的工具链，可以直接打开工程或按当前源码文件进行编译链接。

## 扩展建议

- 把游戏初始化逻辑统一到 start/reset 函数中，避免在窗口消息里直接清空数组。
- 增加“重新开始”和“结束状态”的明确切换，进一步完善 gamestatus 的语义。
- 将棋盘坐标、窗口尺寸和资源路径封装成配置常量，提升可维护性。
- 为说明窗口增加关闭按钮或自动释放逻辑，改善交互体验。

## 结论

本项目的核心结构非常清晰：main.c 负责窗口和渲染，game.c 负责规则和状态，game.h 负责接口统一。当前实现已经具备完整的五子棋闭环流程，适合作为 Win32 版小游戏的基础架构。
